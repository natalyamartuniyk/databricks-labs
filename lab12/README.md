## Part A — RAG

### Data preparation
- `trending_date` is a string in `yy.dd.MM` format, so `MIN`/`MAX` on it compares text, not dates. It is parsed with `to_date`.
- 7 synthetic test rows from 2026 are removed by the business period from the config (same rule as the gold layer).
- Silver has one row per video per trending day (≈6.4 rows per video). Without deduplication the same video would
  fill the whole top-k. The latest row per `video_id` is kept → 6,351 documents.
- Cleaning: literal `\n` from the CSV, URLs, decorative symbols, the `"No description"` placeholder; tags `"a"|"b"` → `a, b`.

### Chunking
- Median description ≈ 826 characters (~200 tokens), p90 ≈ 2,145, max 5,123.
- `chunk_size = 1200`, `chunk_overlap = 150` characters, cut on word boundaries.
- Only the body (tags + description) is split; every chunk starts with a header (title, channel, category),
  so a chunk from the middle of a long description still says which video it belongs to.
- `chunk_id = <video_id>_<n>` is deterministic, so MERGE and CDF only see real changes.

### Embeddings: managed → self-managed
The first index used managed embeddings. The sync measured **2,233 ms per row** (estimate: 5.5 hours for 8,743 chunks),
because the shared pay-per-token endpoint was called row by row.
A test with `ai_query` gave **68 ms per row** (≈33× faster), so embeddings are computed in `02` and the index reads the
`embedding` column (`embedding_dimension = 1024`).

- A vector is computed only for new chunks or chunks whose text or `embedding_model` changed; others reuse the stored vector.
- `ai_query` results are written once to a staging table before MERGE, because MERGE may read its source twice.
- Every vector is checked (not null, 1024 numbers) before MERGE.
- Result: a rerun with no data changes makes **0 model calls** and the index has nothing to resync.

### Model choice
- Unity Gateway path (`/ai-gateway/mlflow/v1`) returned 404 in this workspace.
- Claude models returned `403 PERMISSION_DENIED: Access to this model is disabled for your workspace`.
- `gpt-oss-120b` is a reasoning model: it spends tokens on reasoning before answering (slower, more expensive).
- Chosen: `meta-llama-3-3-70b-instruct`, `temperature = 0`, `max_tokens = 500`.

### Prompt
The system prompt tells the model to use only the numbered context, answer exactly
`I don't know based on the available videos.` when the context has no answer, cite sources as `[n]`,
and never invent titles, channels or numbers.

Metrics: `retrieval_hit` (expected video in top-5), `keyword_correct`, `said_idk`,

Examples without retrieval (hallucinations): the Santa Ana wind peak "Wednesday" (data: Thursday),

Limitations: keyword matching is coarse (one no-RAG answer contained the right keyword next to a wrong claim),
and the judge is also an LLM, so its verdicts were checked by hand.

## Monitoring and logging
- Every `answer_question` call appends one row to `rag_qa_logs`: question, answer, `use_retrieval`, filters,
  retrieved `chunk_id`s and scores, model, prompt/completion tokens, latency, status and error.
  Failed calls are logged too (`finally`), and a logging failure never breaks the answer.
- `caller` separates real questions (`qa`) from evaluation runs (`evaluation`).
- MLflow Tracing recorded each LLM call (prompt, response, tokens, latency) automatically.

## Discussion

**Why RAG beats prompting alone.** On dataset-specific questions RAG answered 5/5 correctly and the plain model 0/5,
confidently inventing days, places and names. On well-known questions the model is often right from memory,
but RAG adds sources that can be checked. Prompting alone cannot know private or new data and cannot cite it.

**Chunk size vs retrieval quality.** Small chunks match precisely but lose context; large chunks keep context
but blur the vector and make the prompt more expensive. Most descriptions fit one 1,200-character chunk, long ones are
split with 150 characters of overlap, and the header in every chunk keeps the video context.
TODO: optional experiment with another `chunk_size` comparing `retrieval_hit` between runs (`run_id`).

**Governance.** Data, the index and the logs are Unity Catalog objects with grants; the app uses a service principal
with minimum privileges; model access is controlled per workspace; question logs are sensitive.

**Cost.** Embeddings are computed once and reused (a rerun costs 0 model calls); `ai_query` is ~33× faster than
row-by-row sync. A RAG prompt was ~1,750 tokens vs ~60 without retrieval (≈28×), so `top_k` and chunk size are
also cost settings. The AI Search endpoint is billed while it exists, so it is created once and deleted after the demo.
